# Data model for tracking a search

Five record types. The guide's Applications tab uses the first; the rest are optional extensions. Keep it this small: you can always add columns later.

## Application (the one the Applications tab stores)
| Field | Meaning |
|---|---|
| `id` | Unique id, generated by the page |
| `company`, `role` | Who and what |
| `url` | Link to the posting |
| `status` | One value from the status ladder below |
| `applied` | Date sent, `YYYY-MM-DD`, empty while "To apply" |
| `note` | Free text: what you tailored, who you spoke to |

## Status ladder
Defined once in `scripts/common.py` (`STATUSES`); the page reads it from there.

| Status | Stage | Meaning |
|---|---|---|
| To apply | planned | Shortlisted, not sent |
| Submitted | open | You sent it |
| OA invited | open | Online assessment or take-home requested |
| OA done | open | Assessment completed |
| Interview | open | Any interview round |
| Offer | won | Offer received |
| Rejected | closed | They said no, or the posting closed on you |
| Withdrawn | closed | You pulled out |

Counts on the page: *Applications sent* = everything not "To apply"; *Active or offer* = open + won; *Closed* = closed.

## Optional extensions
- **Firm**: `name, bucket, tier, ats, slug` (this is `profiles/<name>/companies.csv`).
- **Posting**: `firm, ext_id, title, location, url, description, posted_at, score`. Unique on `(firm, ext_id)`. Output of `fetch_board.py` and `rank.py`.
- **Contact**: `firm, name, title, source, channel, stage (target, messaged, replied, call_done, dormant), last_touch, notes`. For networking.
- **Event**: an append-only log across all records, once you have more than one store (see `scaling-up.md`).

A starter SQL version of all five is in `schema.sql`.

## Where the page keeps application rows
- Published as a Claude artifact with the `db` and `user` capabilities: in the page's private per-viewer database at `data/users/<id>/`, one document per application. It survives reloads and devices.
- Anywhere else (GitHub Pages, a local file): this browser's `localStorage`. Clearing site data erases it, so copy anything you want to keep.

Never put resumes, answers to application questions, or personal identifiers in the shared repo or in a shared database.
